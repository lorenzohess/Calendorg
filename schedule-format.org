* Calendorg Timeblock Specification
For an implementation example see [[file:schedule-example.org][schedule-example.org]].
** Files
Two files, one grammar.

| File                               | Owner | Contents                                |
|------------------------------------+-------+-----------------------------------------|
| =$SCHEDULE_DIR/schedule.org=         | you   | commitments, fixed blocks, sleep, types |
| =$SCHEDULE_DIR/calendorg-blocks.org= | app   | allocated blocks                        |

Calendorg read both but only modifies the second. 
** Block grammar
To add a timeblock:
#+begin_example
- DAY HH:MM-HH:MM TYPE [@COMMITMENT] [label]
  : optional comment
#+end_example

- =DAY= is one of =MON TUE WED THU FRI SAT SUN=.
- Times are 24-hour, zero-padded, =HH:MM=.
- =TYPE= is a lowercase token declared under =* Types=.
- =@COMMITMENT= is optional. It names a commitment declared under =* Commitments=, and the block's hours count toward it.
- =label= is optional free text to provide timeblock tagging functionality. When absent the type name is used, title-cased with hyphens turned into spaces, so =ice-hockey= renders as "Ice hockey".
- A comment is a new line indented and prefixed with =:=.
** Org Heading Sections
Four top-level heading sections are required, and each has its own line format for content. Section order does not matter, and anything outside a recognized heading is ignored.
*** Commitments
#+begin_example
- TOKEN HOURS
#+end_example

=HOURS= is the *total* weekly budget, meetings included. 
*** Blocks
Timeblocks following block grammar.
*** Sleep
Your sleep hours for the entire week. The time window represents an uncertainty range, which is visualized as a gradient.
#+begin_example
- wake HH:MM-HH:MM
- sleep HH:MM-HH:MM
#+end_example
*** Types
#+begin_example
- TOKEN #RRGGBB
#+end_example

Adding a type here is all that is needed to make it render and appear in the legend. =allocated= must be declared, and it is the type Calendorg writes.
** Rules
- A block span must be positive, so a block running past midnight ends at =24:00= or =25:00= rather than wrapping: =WED 21:30-25:00= means 21:30 to 01:00.
- The grid runs 08:00 to 01:00. Times earlier than the grid start belong to the preceding day's column, so a =00:30= block sits at the bottom of the previous day.
- Every block is weekly. No dates appear anywhere in either file.
- Overlapping blocks are legal and will be visually overlapped.
** Parsing
Dispatch on the current heading, then match one regexp per section.
#+begin_src emacs-lisp
(defconst calendorg--re-block
  (concat "^[ \t]*-[ \t]+\\([A-Z]\\{3\\}\\)"
          "[ \t]+\\([0-9]\\{2\\}:[0-9]\\{2\\}\\)-\\([0-9]\\{2\\}:[0-9]\\{2\\}\\)"
          "[ \t]+\\([a-z][a-z-]*\\)"
          "\\(?:[ \t]+@\\([^ \t]+\\)\\)?"
          "\\(?:[ \t]+\\(.*?\\)\\)?[ \t]*$"))

(defconst calendorg--re-comment    "^[ \t]+:[ \t]?\\(.*\\)$")
(defconst calendorg--re-commitment "^[ \t]*-[ \t]+\\([^ \t]+\\)[ \t]+\\([0-9]+\\(?:\\.[0-9]+\\)?\\)[ \t]*$")
(defconst calendorg--re-sleep      "^[ \t]*-[ \t]+\\(wake\\|sleep\\)[ \t]+\\([0-9]\\{2\\}:[0-9]\\{2\\}\\)-\\([0-9]\\{2\\}:[0-9]\\{2\\}\\)[ \t]*$")
(defconst calendorg--re-type       "^[ \t]*-[ \t]+\\([a-z][a-z-]*\\)[ \t]+\\(#[0-9a-fA-F]\\{6\\}\\)[ \t]*$")
#+end_src

Block groups are day, start, end, type, commitment, label.
** Stats
For each commitment:

- =target= = declared hours − hours of =meeting= blocks referencing it
- =allocated= = hours of =allocated= blocks referencing it
- panel shows =allocated / target=
